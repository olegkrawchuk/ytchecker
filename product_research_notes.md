# Продуктові нотатки: чому scope навмисно вузький

Коротка фіксація висновків з продуктового/конкурентного дослідження (серпень 2026), щоб не переоцінювати проєкт і не повертатись до вже відкинутих ідей без причини.

## Контекст використання

Це **персональний інструмент** для одного стрімера й аудиторії, яка замовляє музику донатами через [Donatik](https://donatik.ua) — не продукт для ринку. Це визначає майже всі рішення нижче.

- Трек, замовлений донатом, **грає одразу, без затримки** — вікна для "перевір, а потім дозволь" немає.
- **У Donatik немає публічного API/webhook** на подію донату з треком (перевірено: немає developer-розділу, `docs.donatik.ua` не існує, немає інтеграцій на GitHub). Автоматична перевірка "в момент донату" технічно неможлива без співпраці з Donatik напряму.
- Єдиний існуючий захист — **стример і модератори слухають наживо** й реагують на слух. Жодного інструменту (сайт, чат-бот, розширення) вони реально не використовують під час стріму — немає вільної уваги, поки йде гра.

## Що це означає для продукту

**Live-переривання інструмент профілактично не вирішує** — і не може, поки Donatik не дасть програмний доступ до черги запитів. Це не недолік реалізації, а зовнішнє обмеження.

Тому інструмент лишається тим, чим є: **ручний точковий чекер одного треку** — для випадків, коли хтось (стример, модератор, чи сам донатер) сам вирішив перевірити конкретне посилання заздалегідь.

## Конкурентний ландшафт (стисло)

- Прямі аналоги вже існують: **Mubert** має окремий Twitch-специфічний чекер (live vs VOD-подібний поділ), **TuneRef** — безкоштовне Chrome-розширення з інлайн-перевіркою прямо в браузері. Технічного рову тут немає — усі використовують ті самі публічні API (AudD/ACRCloud/YouTube Data API).
- Більший сусідній ринок — **проактивні каталоги** (Soundtrack by Twitch, Pretzel Rocks, StreamBeats): дають стримеру готову безпечну музику замість перевірки того, що він сам обрав. Це вирішує набагагато частіший сценарій (фонова музика 24/7), ніж точкова перевірка — і саме там основна маса уваги ринку.
- **Висновок:** розширення до каталогу чи повноцінного продукту не розглядається — цей сегмент ринку вже зайнятий усталеними гравцями.

## Розглянуті й свідомо відхилені ідеї

| Ідея | Чому відхилено |
|---|---|
| Партнерська рекомендація безпечної альтернативи (Pretzel Rocks тощо) на RED/YELLOW | Немає сенсу без наміру рости як продукт |
| Чат-бот `!check` для модераторів | Модератори й так не встигають ним користуватись під час стріму — та сама проблема відсутності вільної уваги |
| Автоматична перевірка "в момент донату" | Технічно неможлива — у Donatik немає API/webhook |
| Batch-скан VOD після стріму (технічно реалізовано через `enterprise.audd.io`, ~$0.60/год запису) | **Технічно реалістично**, але недоцільно в цьому контексті: постійні витрати на приватний інструмент без монетизації чи компенсації не виправдані |
| Розширення до власного каталогу пре-кліренс музики | Великий чужий ринок з усталеними гравцями, не для персонального інструменту |

## Якщо колись повертатись до цього

Єдина обставина, яка реально відкриває нові варіанти — це якщо Donatik (чи інша платформа донатів, напр. DonationAlerts, яка публічне API вже має) дасть програмний доступ до подій запиту треку. До того часу зазначені обмеження лишаються чинними.
